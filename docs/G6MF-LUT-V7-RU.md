# G6 MF v7: эксперимент с размером цветовой LUT

Это проверка гипотезы по профилю v6, а не подтверждённое исправление FPS.
Исследован CoreDisplay 291.4 из Tahoe 25G241, UUID
24682CF5-C129-3A3F-91C7-80A228552372 — совпадает с библиотекой в sample.

В RunFullDisplayPipe размер цветовой таблицы выбирается по Metal SPI
maxTextureWidth1D и ограничивается сверху 16384. При заполнении RGB таблиц
CombineLUTs вызывает CurrentHeadroom для каждой точки; профиль показывает
конкуренцию за mutex в этом месте. Это объясняет, почему стоит проверить
меньшую таблицу, но само по себе ещё не доказывает улучшение на ноутбуке.

## Что меняется

Маленький C-загрузчик занимает место исполняемого файла NVMTLDriver.bundle.
Он загружает сохранённый оригинал NVMTLDriver.g6mf-original через dlopen.
Только в процессе WindowServer на классе NVMTLDevice добавляется override
maxTextureWidth1D, возвращающий min(оригинальный предел, 1024).
Базовый класс Metal и другие GPU не изменяются. Обычные приложения используют
оригинальный предел. Изменяется предел всех запросов 1D-текстур WindowServer
на этом NVIDIA устройстве; это не отдельный документированный API размера LUT.

Цветовой путь CoreDisplay сохраняется, но LUT может иметь меньшую точность.
Проверить градиенты, оттенки и эффекты после установки обязательно; идеальная
тождественность цветов не заявляется. В 8-битном SDR тест имеет смысл, однако
HDR/EDR этим экспериментом не проверены. NVK, переводчик шейдеров и оригинальный
NVMTL не пересобираются. EFI, kexts, KC и частота панели не меняются.
Библиотеки Apple не патчатся и в комплект не включены.

## Установка на уже рабочий v6

    sudo bash /Volumes/1401/NullMoth-G6MF-Bridge-v7-LUT/install-lut.sh

Установщик принимает только известный оригинальный NVMTL 2.6.4 и стек v6
(NMIntelFB 0.1.4 / NVAccel 0.1.3), сохраняет весь Metal bundle и конфигурацию
на APFS, подписывает кандидата штатным codesign и заменяет bundle переименованием.
Потом отдельный Metal probe меняет только собственное libc progname на
WindowServer, проверяет предел 1024, blit/readback и две compute dispatch.
Это проверка политики процесса, не запуск второго настоящего WindowServer.
Ошибка/отсутствие ожидаемых маркеров вызывает автоматическое восстановление.
В текущем WindowServer плагин не выгружается и не подменяется в памяти.

Только после LUT TEST READY перезагрузиться. Затем:

    sudo bash /Volumes/1401/NullMoth-G6MF-Bridge-v7-LUT/profile-perf.sh

Двадцать секунд двигать окно, дождаться PROFILE COLLECTION COMPLETE. Оценить
плавность курсора, Genie/Glass и плавные градиенты. Вернуться в Linux со сбором.
Однократный автосбор следующей загрузки также включён на случай чёрного экрана.

## Контроль и откат

Чтобы убрать ограничение без смены загрузчика:

    sudo bash /Volumes/1401/NullMoth-G6MF-Bridge-v7-LUT/set-lut-limit.sh 0

Перезагрузиться и повторить тот же профиль. Это контроль с оригинальным пределом.
Доступны также 1024, 2048, 4096, 16384; значение читается при загрузке плагина,
поэтому для сравнения нужен новый сеанс WindowServer (проще перезагрузка).
Нормальные приложения при любом значении сохраняют исходные ограничения.

Полный откат плагина:

    sudo bash /Volumes/1401/NullMoth-G6MF-Bridge-v7-LUT/rollback-lut.sh ПУТЬ_ИЗ_last-lut-backup.txt

В Recovery скрипт принимает вторым аргументом корень Data-тома, а путь бэкапа
нужно указывать так, как он виден в Recovery. После отката перезагрузиться.
При чёрном экране подождать пять минут для автосбора и вернуться в Linux.

## Проверки

Linux cross build x86_64 Mach-O bundle + executable; без Xcode на целевом Mac.
Mock-runtime/ASan/UBSan: загрузка оригинала, изоляция процесса/класса, inherited
method safety, отказ при неверном ABI/конфиге, повторный вызов без рекурсии.
Реальные Bash installer/rollback с mock Darwin tools: успех и восстановление,
ошибки подписи, probe, отсутствующий маркер и ошибка установки автосбора.
Это локальные проверки. Нативный codesign/Metal probe и аппаратный результат
ещё должен подтвердить запуск установщика в Tahoe.

Для извлечения библиотеки при локальном анализе использован ipsw:
https://blacktop.github.io/ipsw/docs/guides/dyld/

Аппаратный тест 30 октября: native probe и реальный WindowServer подтвердили
LUT 1024; копирования на панель выросли с 20.40 до 62.35/с, рывки остались.
Подробности и ограничения сравнения: [результат v7](G6MF-LUT-V7-RESULT-RU.md).
