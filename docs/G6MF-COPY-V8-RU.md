# v8: сравнение алгоритмов копирования на Intel

Эксперимент после повторных замеров v7: 63.6–66.2 копирования/с, ready/pageoff
2.55–2.65 мс, CPU copy 1.95–1.99 мс, весь обработчик 4.82–4.94 мс.
Компиляция шейдеров в повторных sample не наблюдалась; LUT/mutex и
композитинг остаются существенными. Ускорение одного копирования не обещает
165 FPS и может вообще не уменьшить рывки, если доминирует другой этап.

## Изменение

Только NVAccel 0.1.4: для выровненных на 8 байт строк новый вариант читает и
пишет по 64 бита, с развёрткой на 8 пикселей. На нечётных/невыровненных строках
и хвостах остаётся ограниченный 32-битный доступ. Используются только целые
регистры, без SIMD/FPU. Указатели volatile, sfence сохранён. Размеры, формат,
проверка ёмкости, GPU fence и pageoff остаются прежними. Это CPU-копирование,
не zero-copy и не прямой DMA из NVIDIA в Intel.

После загрузки по умолчанию работает старый вариант. Переключатель:

    sudo sysctl debug.nvaccel_muxless_copy64=1

Значение 0 возвращает прежний путь сразу; перезагрузка также возвращает 0.
Выбор читается один раз на транзакцию. Переключатель действует только на
копирование в NMIntelFB, не на нативные NVIDIA framebuffer.
NMIntelFB, NVRMAGDC, EFI, Metal-плагин и LUT 1024 сохраняются.

## Установка и сравнение

Из обычной Tahoe 25G241 с рабочими v6/v7:

    sudo bash /Volumes/1401/NullMoth-G6MF-Bridge-v8-Copy/install-copy.sh

Только после COPY UPDATE READY перезагрузиться. Установщик сначала проверяет
кандидат Auxiliary KC, сохраняет компоненты/KC, затем проверяет live KC;
при ошибке обновления KC изменения откатываются. Готовые x86_64 kexts находятся в комплекте,
Xcode и сборка на этом Mac не нужны.

Затем:

    sudo bash /Volumes/1401/NullMoth-G6MF-Bridge-v8-Copy/compare-copy.sh

45 секунд повторять движения окон/анимации для прогрева. Далее два раза
выполнить одинаковое движение окна в течение 20 секунд по подсказке:
сначала режим 0, затем 1. Между ними полный сбор может занять около минуты;
дождаться следующей подсказки. Финальный маркер COPY COMPARISON COMPLETE.
Скрипт возвращает начальное значение переключателя даже при ошибке/сигнале.
Он не меняет LUT. В perf-отчётах сохранён copy-mode.txt.

Сравнивать CPU copy, total, частоту успешных копирований и хвост entry
histogram >=28/40 мс. Широкие записи сами по себе не устраняют ожидания
CoreDisplay и CPU-композитинг. Только реальный тест покажет полезность на
write-combined Intel aperture; Linux RAM-тест не подтверждает его скорость.

## Откат

Мгновенно отключить новый алгоритм:

    sudo sysctl debug.nvaccel_muxless_copy64=0

Полностью восстановить предыдущий NVAccel и Auxiliary KC:

    sudo bash /Volumes/1401/NullMoth-G6MF-Bridge-v8-Copy/rollback-bridge-macos.sh ПУТЬ_ИЗ_last-bridge-backup.txt

После полного отката перезагрузиться. Предыдущий Metal-плагин с LUT и
работающий рабочий стол остаются частью сохранённого v7 состояния.

## Проверки

ASan/UBSan: равенство старого/нового копирования, пиксели, padding/canary,
чётные/нечётные ширины и шаги строк, смещения 0/4 байта, отказ при коротких
буферах без записи, точная граница PROT_NONE и полный кадр 1920×1200.
Cross-build и проверка импортов/метаданных Mach-O выполняются до упаковки.
Аппаратная плавность и скорость широких WC-записей пока не проверены.
