# G6 MF: сборка через GitHub Actions

Workflow: `.github/workflows/g6mf-kexts.yml`.

Локальная сборка на ноутбуке с Tahoe не нужна. GitHub Actions компилирует
четыре kext на `macos-26-intel` штатным Xcode toolchain. Intel-панель, RTX/GSP,
Metal и WindowServer проверяются отдельным запуском на самом ноутбуке.

## Запуск

Разместить полный исходник с патчем v1 и workflow в своём GitHub-репозитории.
Если используется старый архив v1, применить к нему `g6mf-ci.patch` из обновлённого
набора. CI-only патч добавляет workflow, упаковщик, сборщик диагностики и этот
документ; основной патч моста повторно применять не нужно.

После размещения workflow в default branch открыть Actions → G6 MF kexts →
Run workflow. Target `all` собирает NMIntelProbe, NMIntelFB, NVAccel и NVRMFB;
`probe` собирает только отдельный диагностический kext. Push/PR с изменениями
исходников также запускает полный набор. Никаких секретов workflow не требует.

## Артефакты

После успешной сборки скачать `g6mf-all-x86_64-COMMIT` либо
`g6mf-probe-x86_64-COMMIT`. Внутри — `NullMoth-G6MF-v1.tar.gz` и SHA256SUMS.
Архив tar.gz сохраняет структуру bundles и права файлов при передаче через
GitHub artifacts. Распаковать его в корень флешки 1401.

Комплект включает готовый probe, инструменты включения/отката EFI, сборщик
macOS-диагностики, manifest и логи. При target all добавляются три кандидата
моста. Они требуют соответствующего полного стека NullMoth; workflow собирает
изменённые kernel-компоненты, а не заново NVRM/GSP/Metal plugin/NVK.

Артефакты скомпилированных kext не подписаны Apple. Сборка не устанавливает
драйвер и не меняет EFI или графический пакет пользователя.

## Проверки

Перед native-сборкой выполняются CPU regression tests на Ubuntu, включая
Intel-only регистрацию, границы копирования, ожидание fence, сохранение/откат
EFI и прежние headless/pageoff тесты. Внутренний тест на ASan/UBSan также
проверяет, что исходный upstream проваливает Intel-only regression.

Перед упаковкой проверяются Mach-O x86_64/MH_KEXT_BUNDLE, `_kmod_info`,
совпадение bundle ID/версии с Info.plist и SHA-256 каждого ожидаемого бинарника
с manifest. Неполный или изменённый набор не публикуется как готовый комплект.
Логи тестов/сборки выгружаются и при ошибках. Actions и внешние зависимости
закреплены по commit SHA.

В этой локальной сессии workflow проверяется actionlint, а упаковщик — на
уже собранных бинарниках. Реальный результат GitHub Actions появится только
после push и запуска в выбранном репозитории; локальная проверка не является
успешным облачным CI run.

Дополнение probe 0.1.2: CI также проверяет отсутствие atexit/TLS-импортов
и наличие секций инициализации/завершения kext. Регрессионный тест включён
в Ubuntu job, а проверка реальных бинарников — в native build до упаковки.
