# Контроль v9 с serial=0

Источники: perf-20261030-115818-984 / profile-20261030-115817-971.
Конфиг serial=0, copy64=0. Полный сбор завершён; исходные файлы вне Git.

Оценка по VBL-окну: 1296 копий / 20.022040 с = 64.73 копии/с,
средний entry gap 15.4476 мс. Fence 0.3154, ready 2.6551, copy 1.9913,
total 4.9712 мс. Гистограмма (<7, 7–12, 12–20, 20–28, 28–40, >=40 мс):
1, 366, 726, 187, 12, 5. Ошибок транзакций, GPU timeout и copy_skip в окне нет.

При serial=1 ранее: 97.27 копии/с, entry 10.1341 мс, total 4.5181 мс;
28 удержаний, 3 интервала >=40 мс. Теперь с отключением изменения снова
наблюдается параллельный путь: collapsed mutexwait 2754, mutexdrop 1310;
для serial=1 было 16 mutexwait. Это поддерживает причинную связь v9 с
уменьшением конкуренции и более частыми транзакциями. Измерения всё ещё
ручные, в разных загрузках; копии/с не равны FPS приложения. Период VBL
в контроле 6.1099 мс, в предыдущем serial=1 5.9525 мс; условия не идентичны.

Вывод: контроль согласуется с выигрышем v9. Есть основания использовать
serial=1 как текущий рабочий эксперимент. Дальнейшая область работы —
перенос staging → IOSurface → Intel и причины copy_skip при высокой частоте.
Разрешать копирование неподтверждённых данных нельзя. Стабильные 165 FPS
и отсутствие всех рывков пока не подтверждены.
